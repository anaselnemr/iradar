What iRadar is

iRadar opens {{ '{:,}'.format(f.pages) }} Infineon.com pages on a schedule and tells you what actually changed on them since last time — wording, documents, images, videos, boards, prices.

It exists because the alternative is opening a page and trying to remember what it said last month. Right now it is tracking {{ '{:,}'.format(f.tracked) }} individual items across those pages, including {{ '{:,}'.format(f.docs) }} distinct documents, and {{ f.people }} {{ 'person is' if f.people == 1 else 'people are' }} using it.

The weekly check

Runs {{ every }} at {{ at_time }}, automatically. Nobody starts it. Next one: {{ next_run }}{% if run_hours %}. The last one took about {{ run_hours }}{% endif %}.

  1. Each page is opened in a real browser Not downloaded as HTML — genuinely rendered, the way you would see it. It scrolls to the bottom so anything that loads late appears, opens tabs and accordions, and waits for images to finish arriving.
    If a page only half-loads it is thrown away rather than saved. A half-loaded page would become next week's reference, and then everything missing from it looks like it was deleted.
  2. What is on it is written down The visible text, every image, the full library — documents, videos, boards, design resources, partners — the price, and a full-page screenshot.
  3. It is compared with the previous capture Five signals, listed in the next section. Any one of them is enough to raise it for review.
  4. Anything raised is captured a second time, straight away Before the run finishes. If the difference does not appear again it was the website being inconsistent rather than an edit, and it is dropped without you ever seeing it.
    This single step removes most false alarms.
  5. Pages that fail get two more attempts A page that times out is retried at the end of the run. Only something that fails every attempt is recorded as an error — one bad moment is not a verdict.
  6. What survives lands in your queue On the Dashboard, marked Updated. Nothing else is deleted or altered; the previous version stays until you decide.

What counts as a change

SignalRaises a page when
TextWording is added, removed or edited.
Text that merely moved does not count. The same lines in a different order is a layout change, not an edit.
LibraryA document, video, board, design resource or partner is added or removed — or one of their details changes: version, date, size, price.
ImagesA picture appears on, or disappears from, the page.
ScreenshotMore than {{ s.visual_threshold }}% of the pixels differ, or the page height moves by more than {{ s.height_threshold }}px.
A real visual change, not a word shifting one line down.
File updatesA file is republished at the same address. The page looks identical and nothing on it moved, but the datasheet behind the link is a new one. Listed separately under File updates on the Dashboard.

What it deliberately ignores

Every item here caused a flood of false alarms before it was handled. If you ever wonder why something did not come up, it is probably one of these.

IgnoredWhy
Stock levelsThe number in the buy box changes overnight on its own — a part showing "4387 in stock" reads 4382 the next morning. The price is still watched, so a genuine price move still comes up.
The developer community feedIt re-sorts and re-dates itself constantly. Whether the widget is present, empty, or has discussions is still tracked — only its churn is ignored.
"Latest news" and the mega-menuIdentical on every page, and updated centrally. One retired news thumbnail once raised 585 pages at the same time.
Tabbed sections loading differentlyTwo visits can land on different tabs of the same section. Their contents are tracked item by item instead, which does not flap.
Timestamps and "3 days ago"They change by themselves without anybody editing anything.

An admin can adjust what is ignored under {% if is_admin %}Settings{% else %}Settings{% endif %}.

Reviewing an update

Open one from the Dashboard. You see exactly what moved — the wording before and after, which documents came and went, and the two screenshots with the changed areas boxed.

Then one of two buttons:

ButtonWhat it doesUse it when
Accept Confirms this is the page now. It becomes the reference the next check compares against. The change is real — whether it is important or not.
Reject Says "do not use this capture as the reference". The previous version stays. The capture is wrong — something clearly did not load.

Accept is the normal one. Reject is for when iRadar got the page wrong, not for when you dislike what Infineon published. Either way the page goes back to normal afterwards — nothing is left hanging or waiting on you.

Notes

Every page, document, board and update has a Notes box at the bottom. It is for the reasoning, not the fact — "checked with marketing, the new subheadline is intentional, leaving it".

Whoever opens that page next reads it without having to ask you, which is the whole point: the decision outlives the conversation.

  • Edit or delete your own at any time
  • Mark any note done once it has been handled
  • See everything anyone has written under Notes, newest first

What it does not do

  • It does not find new pages by itself. iRadar watches the {{ '{:,}'.format(f.pages) }} pages it has been given. If Infineon publishes a new one, somebody has to add it{% if is_admin %} under Add pages on the Dashboard{% endif %}.
  • A few finder pages only capture their first page of results.
  • Gated documents — the ones behind a MyInfineon login — cannot be previewed, because all we can see is the login wall.
  • It reports, it does not judge. Whether a change matters is your call; iRadar only promises to notice it.
